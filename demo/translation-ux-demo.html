Translation UX — proposal demo

Two problems, one demo: translated markdown renders as raw text, and slow translations leave the bubble unchanged (no feedback until it silently flips). Left card reproduces today's behaviour; right card is the proposed implementation — the box shows a translating state first, then only the final text, and falls back to the original if the request fails. While waiting, the visitor can cancel and get the original text back immediately.

Same marked + DOMPurify pipeline for original & translated state machine: idle → translating → translated | failed cancel while waiting (AbortController) no layout jump, no silent swap

today  v1.2.0 behaviour

Click translate: the bubble keeps the English text (only the tiny link shows “…”), then swaps to the translation rendered as plain text.

2 · Translation as a UI state MessageBubble.tsx + useChatSession.ts + translationCache.ts

// per message (manual button AND auto-translate)
type Tx = 'idle' | 'translating' | 'translated' | 'failed'
const ctrl = useRef<AbortController>()          // one per message

// trigger: replace the bubble content immediately
ctrl.current = new AbortController()
setTx('translating')          // skeleton + spinner + Cancel
try {
  const text = await onTranslate(message, ctrl.current.signal)
  setTx('translated')         // renderMarkdown(text)
} catch (e) {
  if (ctrl.current.signal.aborted) setTx('idle') // cancelled by the user
  else setTx('failed')        // original + "Retry" hint (auto-clears)
}

// Cancel button → ctrl.current.abort(); setTx('idle')
// fetchTranslation() gains an optional { signal } → passed to fetch()
